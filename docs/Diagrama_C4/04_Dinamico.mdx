# Diagrama Dinâmico — Abertura de Chamado

Como os componentes colaboram quando o aluno envia uma solicitação pelo assistente do catálogo.

```mermaid
%%{init: {
  "theme": "base",
  "themeVariables": {
    "primaryColor": "#f7d9d6",
    "primaryTextColor": "#1c1c1e",
    "primaryBorderColor": "#e8281a",
    "lineColor": "#e8281a",
    "actorBkg": "#fdf1f0",
    "actorBorder": "#e8281a",
    "actorTextColor": "#1c1c1e",
    "activationBkgColor": "#f7d9d6",
    "activationBorderColor": "#e8281a",
    "noteBkgColor": "#232326",
    "noteTextColor": "#f5f5f5",
    "noteBorderColor": "#e8281a"
  }
}}%%
sequenceDiagram
    autonumber
    actor Aluno
    participant Web as Aplicação Web
    participant Auth as Autorização
    participant Tickets as Chamados
    participant Anexos as Anexos
    participant Notif as Notificações
    participant DB as Banco (Prisma)
    actor Equipe as Equipe do setor

    Aluno->>Web: Preenche o assistente (serviço, dados acadêmicos, campos, documentos) e confirma na revisão
    Web->>Auth: POST /tickets (JWT)

    alt Token inválido ou expirado
        Auth-->>Web: 401
        Web->>Web: Renova a sessão (refresh) ou volta ao login
    else Token válido
        Auth->>Tickets: Encaminha a requisição
        Tickets->>DB: Gera protocolo TCK-XXXXXX
        Tickets->>DB: Procura setor cujo nome contém o "setor provável"
        Note over Tickets,DB: Sem setor correspondente, o chamado fica sem setor (backend#114)
        Tickets->>DB: INSERT chamado (status ABERTO)
        Tickets->>DB: INSERT histórico (— → ABERTO)
        Tickets->>Notif: Notifica solicitante, responsável e membros do setor
        Notif->>DB: INSERT notificação in-app
        Tickets-->>Web: 201 Created (chamado)

        loop Para cada documento escolhido na etapa 4
            Web->>Anexos: POST /tickets/:id/anexos
            Anexos->>Anexos: Grava o arquivo
            Anexos->>Notif: Notifica novo anexo
        end

        Web-->>Aluno: Abre a página da solicitação ("criada com sucesso")
        Equipe->>Web: Vê o chamado em Todos os Chamados e começa o atendimento
    end
```

Diferenças em relação à versão original deste diagrama:

- O serviço do catálogo **não é validado** na criação (não há resposta 422) — [backend#120](https://github.com/4dsm2026/backend_fatecProjeto/issues/120).
- Os anexos são enviados **depois** que o chamado é criado, um por requisição.
- O sistema grava o **histórico de status** já na abertura.
- A equipe só é notificada se o chamado tiver setor (ou responsável).
